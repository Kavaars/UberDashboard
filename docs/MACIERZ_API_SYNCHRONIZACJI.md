Stan: 2026-11-06, baza `acbeb66` i etap `google-access-20261106`. Publiczne API: Microsoft Graph v1.0 i Google Calendar v3. To opis implementacji i pozostałych bramek, nie certyfikat zgodności ani odbiór na rzeczywistych kontach.

Transport pomocniczy endpointu nie oznacza gotowej funkcji. Załączniki, Drive, konferencje, pełna edycja serii, etykiety/godziny pracy kalendarzy i katalog kategorii wymagają kolejnych etapów oraz własnych prób kontraktowych. Aktualny pełny zakres i ograniczenia: [stan synchronizacji](SYNCHRONIZACJA_DWUKIERUNKOWA.md).

Wspólna baza używa SQLite 8 i formatu dokumentów synchronizacji 5, również dla istniejących zadań/wydarzeń. Kopia przed migracją zachowuje oryginał; atomowa migracja podnosi format oraz rewizję CAS, aby otwarta starsza aplikacja nie pominęła nowych zabezpieczeń subskrypcji. Nie zmienia treści paneli, ID, kolejki ani kursorów. Usunięcie subskrypcji zachowuje lokalne dokumenty i blokuje ich wysyłkę do czasu potwierdzonego ponownego dodania tego samego ID. Niewysłana zawartość blokuje wypisanie; zdalne wypisanie tworzy konflikt. Brak wpisu CalendarList nie dowodzi globalnego usunięcia: katalog sprawdza wcześniej znany zasób dodatkowym GET.

CalendarList i ACL korzystają z syncToken, stron i tombstone (ACL: role=none). Ponieważ delta CalendarList pomija część zmian właściwości tylko do odczytu, aktualne role/nazwy odświeżane są osobnym pełnym odczytem metadanych bez zmiany kursora. ACL odświeża kontekst kalendarza i tożsamość kalendarza głównego. Niepewny POST subskrypcji uzgadnia znane ID; niepewna reguła ACL z ID nadanym przez Google wymaga ręcznego wskazania reguły o identycznym scope, bez automatycznego POST.
